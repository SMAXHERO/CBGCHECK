# 产物类型 × 验收档案

A 在写 `acceptance.json` 时按每个产物的 `artifact_type` 套用。混合交付请拆成多个产物，各自声明类型。

## code（源码、脚本、补丁）

**L1 自测（B）**

- 按计划命令构建/运行，happy path 通过
- 新增代码有对应测试，测试能失败（做过一次反向验证）

**L2 确定性检查（B）**

- 编译 / 静态检查 / 格式检查（退出码 0）
- 单测、集成测试、E2E（按项目能力）
- 覆盖率不低于计划阈值（没有阈值就写“不检查”，不要留空）
- 依赖锁文件存在且未引入禁止依赖
- 密钥 / token 不出现在源码与日志
- 重复运行结果一致（关键路径）

**L3 验收（A）**

- 黑盒从外部按需求复跑命令，不看 B 的测试是否“刚好通过”
- 边界与反例抽检（空值、超长、并发、失败注入）
- diff 审查：只改计划范围内文件
- 回归：原有测试仍全绿

**证据**：命令、退出码、日志、覆盖率报告、diff、sha256。

## doc（方案、说明、报告）

**L1 自测（B）**

- 结构完整：标题层级、目录、章节齐全
- 无占位符（TODO/TBD/待补充）遗留

**L2 确定性检查（B）**

- 事实逐条可溯源（数据、引用、链接、接口名、版本号）
- 链接可访问（能自动检查就自动检查）
- 术语前后一致；单位、时区、数字口径统一
- 代码示例可运行或明确标注伪代码

**L3 验收（A）**

- 评分 rubric：准确性、完整性、清晰度、可执行性各 1–5 分
- 通过线：平均分 ≥ 4 且任一维 ≥ 3
- 抽检关键事实，与实现/源数据比对
- 读者视角：目标读者能否照做

**证据**：检查清单、链接检查日志、rubric 评分表、抽检记录。

## data（数据集、报表、导出）

**L1 自测（B）**

- 产物文件存在、可被目标工具打开
- 行数 / 记录数与计划一致（或说明差异）

**L2 确定性检查（B）**

- schema / 字段名 / 类型 / 取值范围
- 缺失值、重复值、空字符串、异常值统计
- 主键唯一性、外键 / 关联完整性
- 汇总值与明细可对账
- 生成脚本可复现（固定随机种子、输入版本）

**L3 验收（A）**

- 抽样比对源数据（至少覆盖首尾与随机若干条）
- 分布 sanity：均值/分位数/枚举取值是否符合预期
- checksum 或行数核对
- 敏感字段已脱敏

**证据**：schema 校验输出、统计报告、抽样比对记录、生成命令与种子。

## config（配置、部署、CI）

**L1 自测（B）**

- 语法 / schema 校验通过
- 在本地或测试环境加载成功

**L2 确定性检查（B）**

- dry-run / plan 输出符合预期
- 幂等：连续应用两次结果一致
- 密钥不落盘（引用环境变量 / 凭据存储）
- 与目标环境版本兼容（镜像 tag、依赖版本）

**L3 验收（A）**

- 差异审查：只改计划范围
- 回滚路径已验证（或明确标注不可回滚并需人工确认）
- 灰度 / 影响面评估

**证据**：校验输出、dry-run 日志、幂等验证记录、回滚演练记录。

---

## mixed（组合交付）

- 子产物逐个声明真实类型并套用上表
- 额外做需求-产物追溯矩阵：每条需求 → 产物 → 检查项
- 额外做集成检查：子产物拼起来是否可用（接口、路径、版本一致）
- A 的终审覆盖全部子产物，不允许只抽一个
