# 藏宝阁数据面板（阴阳师 · 角色）

把藏宝阁的账号列表变成一块好用的数据面板：**73 项条件实时筛选**、KPI 指标、四类图表、明细表排序分页、多账号横向对比、Excel / CSV 导出与 A4 打印，支持深色 / 浅色主题。

数据不是抓下来的静态文件，而是**每次点「查询」时实时拉取**。

> **⚠️ 先读这一段：线上地址打开是空的，这是预期行为**
>
> 已部署地址：**https://smaxhero.github.io/CBGCHECK/**
>
> 直接打开它**看不到数据**，只会看到一个「未探测到本地查询服务」的引导页。原因：
> 实时查询需要本机运行一个伴随服务（它借用你已登录的浏览器去请求藏宝阁），
> 而**公网页面访问不了你电脑上的 `127.0.0.1`** —— Chrome 的本地网络访问保护会直接拦掉：
>
> ```
> Access to fetch at 'http://127.0.0.1:8791/api/health' from origin 'https://<user>.github.io'
> has been blocked by CORS policy: Permission was denied for this request
> to access the `loopback` address space.
> ```
>
> 这是浏览器安全策略，没有任何配置能绕过。所以：
>
> | 你想做什么 | 该怎么做 |
> |---|---|
> | **看真正的数据面板** | 把仓库 clone 到本机，按下面「快速开始」跑起来，用 `http://127.0.0.1:5173` |
> | 先看看界面长什么样 | 看下面两张截图，或打开[界面示例（静态）](https://smaxhero.github.io/CBGCHECK/design/style-preview.html) |
>
> 一句话：**这个项目本质是「本机工具」，线上那份只是代码的展示位。**

## 它长什么样

左侧条件面板（13 组 / 73 项，与原筛选助手同一套定义）＋ 右侧数据区：

- **KPI**：命中数量、价格中位数与四分位、最快散件/招财一速、平均签到、SSR 与六星均值、高战号占比
- **图表**：价格分布直方图、散件一速分段、平台占比环形图、价格 × 签到年数散点（对数轴）
- **明细表**：14 列可排序、分页、服务器列筛选、行勾选对比、展开看全部亮点标签
- **导出**：Excel / CSV（带 UTF-8 BOM，Excel 不乱码）、打印 A4 横向 PDF（表头每页重复）

## 它是怎么工作的

```
浏览器（本机打开）
   │  POST /api/search      ① 发起查询
   │  GET  /api/result      ② 轮询进度
   ▼
本机伴随服务 127.0.0.1:8791
   │  Chrome DevTools Protocol
   ▼
一个受控的 Edge 窗口（你在这里登录一次藏宝阁）
   │  在页面上下文里 fetch，带着你自己的会话
   ▼
藏宝阁 /cgi/api/query
```

**为什么要这么一个本地服务**：藏宝阁的搜索接口要求登录态，而浏览器 Cookie 按域名隔离——
任何部署在别处的网页都拿不到 `cbg.163.com` 的会话。这是浏览器的安全规则，不是实现问题。
所以「带会话的请求」只能由本机一个受你控制的真实浏览器发出。

这个方案**不绕过任何校验**：请求由页面自己发，带着你自己的登录凭据，
和你在藏宝阁网站上手动搜索没有区别。工具不读取、不保存你的账号密码。

## 快速开始

环境要求：Node.js ≥ 20（用于面板与伴随服务），Python ≥ 3.9（可选，仅核对脚本用）。

**第一步：启动伴随服务**（会弹出一个独立的 Edge 窗口）

```bash
node tools/cbg/scraper-service/server.mjs
```

在那个窗口里**登录一次藏宝阁**。登录态存在 `tools/cbg/scraper-service/profile/`
（独立的浏览器用户目录，不碰你日常浏览器的数据与标签页），之后重启服务依然有效。

**第二步：启动面板**

```bash
cd cbg-web
npm install
npm run dev          # http://127.0.0.1:5173
```

打开后会自动探测服务并查询一次。默认条件是**价格 500~1500 元 + 散件一速 ≥158 + 勾玉 ≥100000**，
可在 `cbg-web/src/config/defaults.ts` 里改。

服务还没起来时，页面会显示启动指引，**不会**显示任何旧数据。

## 目录结构

```
├── cbg-web/                      面板（React + Vite + TypeScript + antd + ECharts）
│   ├── src/
│   │   ├── api/live.ts           伴随服务客户端
│   │   ├── components/           条件面板、图表、表格、对比清单、打印视图
│   │   ├── config/defaults.ts    默认筛选条件
│   │   ├── hooks/                实时数据源、条件 schema、主题
│   │   └── utils/                参数换算、统计、导出
│   ├── public/data/              条件定义（filters.json）、区服清单（servers.json）
│   └── README.md                 ← 详细文档在这里（部署、主题、踩过的坑）
├── tools/cbg/
│   ├── scraper-service/server.mjs  伴随服务（浏览器驱动 + HTTP API）
│   ├── seed_web_data.py            把接口返回解析成可排序的数值字段
│   ├── fetch_cbg.py                数据管道入口（dry-run / live / from-file）
│   ├── check_defaults.py           核对默认条件落到哪些字段
│   └── verify_links.py             核对商品链接拼得对不对
└── .github/workflows/deploy.yml    构建并部署到 GitHub Pages
```

**详细文档请见 [cbg-web/README.md](cbg-web/README.md)**，包含：

- 完整的数据流与接口说明、风控阈值实测结论
- GitHub Pages 部署步骤
- 主题（深色/浅色）的实现约定
- **开发时踩过的坑**：无限更新循环、参数倍率与快照单位不一致、ECharts 按需引入漏组件、
  图表 resize 早于 CSS 回流、两个长得一样的商品 ID……每一条都说明了现象、根因与修法

## 已知限制

| 限制 | 说明 |
|---|---|
| 公网版不能实时查询 | GitHub Pages 上的页面调不到你本机的 `127.0.0.1`（浏览器混合内容策略），只显示「未连接服务」的指引页 |
| 「勾玉」等条件不生效 | 列表接口不返回这些字段（它们属于商品详情数据）。界面会明示「N 项条件未生效」，不会假装筛过 |
| 抓取速度受限 | 实测累计约 250 条会触发站点安全验证，所以默认 4 秒/页、单次最多 8 页（120 条）。被拦后需在浏览器里手动过验证并等冷却 |
| 需要手动登录一次 | 登录这一步没法也不该自动化——工具全程不接触、不存储你的账号密码 |

## 数据与合规

- 抓取的是**藏宝阁公开列表页的聚合信息**（价格、区服、一速、签到天数这类账号属性）；
- 请求由**你自己已登录的浏览器**发出，登录态只存在本地被 git 忽略的目录里；
- 请控制频率（默认已做节流），不要高频批量抓取；
- 仅供个人比价参考，**不要用于商业用途或二次分发数据**。请遵守藏宝阁用户协议，
  因使用不当导致的账号风险由使用者自行承担。
