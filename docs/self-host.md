# 别人怎么用这个仓库

> **想直接照做？看 [getting-started.md](getting-started.md)** —— 那份是从零到能用的分步手册
> （装什么、在哪敲、看到什么才算对、出问题怎么查）。本文更偏「为什么」和「有哪些选择」。

先说清楚这个工具的形态：**界面可以放在公网，数据来自你自己机器上的服务。**

```
公网页面（GitHub Pages）  ──授权后──▶  你本机的伴随服务  ──▶  你登录的浏览器  ──▶  藏宝阁
```

所以你只需要做一件事：**在本机跑起伴随服务并登录一次藏宝阁**。
界面用公网地址（最省事）还是本机地址，都可以。

| 你的情况 | 该怎么做 |
|---|---|
| 只想自己用 | 见第一节 |
| 想有个自己的部署 | 见第二节（Fork + Pages） |
| 想和朋友一起用 | 见第三节：每人各跑一份服务，**不能共用一个** |

## 一、clone 到本机自己用

界面的两种打开方式：

| 方式 | 地址 | 说明 |
|---|---|---|
| **公网地址**（推荐，无需构建） | https://smaxhero.github.io/CBGCHECK/ | 首次打开点「**允许**」访问本地网络 |
| **本机地址**（改代码时用） | http://127.0.0.1:5173 | 需要 clone 下来跑 `npm run dev` |

无论哪种，都**必须在本机跑伴随服务**：

```bash
git clone https://github.com/SMAXHERO/CBGCHECK.git
cd CBGCHECK

# 启动伴随服务（会弹出一个独立的浏览器窗口）
node tools/cbg/scraper-service/server.mjs
#   └─ 在那个窗口里登录一次藏宝阁（只需一次，登录态存在本地 profile 里）
```

如果只是想用面板（不打算改代码），到这里就够了——用浏览器打开公网地址、点「允许」即可。
若要跑本机界面：

```bash
cd cbg-web
npm install
npm run dev
#   └─ 浏览器打开 http://127.0.0.1:5173
```

### 需要预装什么

| 依赖 | 是否必需 | 说明 |
|---|---|---|
| **Node.js ≥ 20** | ✅ 必需 | 面板（Vite）和伴随服务都是 Node 程序 |
| **Edge 或 Chrome** | ✅ 必需 | 伴随服务要拉起一个浏览器窗口发请求；Windows 自带 Edge |
| **Python ≥ 3.9** | ⬜ 可选 | 只有 `tools/cbg/` 下的核对脚本用得到，跑面板不需要 |

### 常见疑问

**换网络要重新配置吗？**
不用。服务和界面都在本机 `127.0.0.1` 上通信，换 Wi-Fi 不影响。
唯一变化是请求的出口 IP 变了——家用宽带/手机热点一般没问题；
如果是公司或机房网络，风控可能更容易被触发（表现是提示需要滑块验证）。

**换电脑呢？**
上面那套依赖重新装一遍，并且**在新电脑上重新登录一次藏宝阁**。
登录态存在 `tools/cbg/scraper-service/profile/`，该目录被 git 忽略（它含 Cookie，
绝不能提交），所以不会跟着代码走——这也正是它安全的原因。

**登录态会过期吗？**
会。失效时界面会显示「需要登录藏宝阁」，回到那个浏览器窗口重新登录即可。

## 二、Fork 一份，部署到自己的 GitHub Pages

部署出来的地址**是能真正用的面板**。打开时浏览器会问**「是否允许访问本地网络上的设备」**
（Chrome 142+ / 新版 Edge 的「本地网络访问」权限）：

| 你的选择 | 结果 |
|---|---|
| **允许** | 面板连上你本机的伴随服务，实时查询全部可用 |
| 拒绝 / 忽略 | 显示「未探测到本地查询服务」的引导页 |

关键点：**它连的是你本机运行的伴随服务**（`127.0.0.1:8791`），不是任何云端后端。
所以想用它，你这台机器上得先把服务跑起来、并且登录过藏宝阁。

步骤：

1. 仓库页右上角 **Fork** → **Create fork**，得到 `你的用户名/CBGCHECK`
2. 在**你自己的 fork** 里打开 **Settings → Pages**
3. **Source 选择 `GitHub Actions`**（不要选 "Deploy from a branch"）
4. 到 **Actions** 标签，若提示工作流被禁用，点
   **I understand my workflows, go ahead and enable them**
5. 之后每次 push 到 `main` 分支，工作流会自动构建并部署，约 1 分半
6. 访问 `https://你的用户名.github.io/CBGCHECK/`

### 不需要改任何代码

`cbg-web/vite.config.mjs` 用的是 `base: './'`（相对路径），
所以仓库叫 `CBGCHECK`、`cbg-panel` 还是别的名字都能直接跑，不用改配置。

### 三个容易卡住的点

| 现象 | 原因与处理 |
|---|---|
| Pages 里找不到 GitHub Actions 选项 | 仓库必须是 **Public**——私有仓库的 Pages 需要付费计划 |
| 部署成功但页面是 404 | Source 选错了，要选 `GitHub Actions`，不是分支部署 |
| Actions 里没有任何工作流 | fork 来的仓库默认可能禁用工作流，去 Actions 页手动启用一次 |

## 三、多人使用时的实际情形

**每个使用者用的都是自己机器上的服务和自己的账号。**

公网页面能连本机服务，靠的是浏览器弹出的「允许访问本地网络」授权——它授权的目标是
**「这台电脑的 127.0.0.1」**，不是某个人的服务器。所以：

| 场景 | 结果 |
|---|---|
| 你把公网地址发给朋友 | 他打开后**用的是他自己机器上的服务**；他没跑服务，就只看到引导页 |
| 你想让朋友用**你的**服务查数据 | 做不到，除非把你的服务暴露到公网（云服务器 / 内网穿透）。那条路的成本、风控与合规风险另算 |
| 你自己换台电脑打开同一个地址 | 同样连的是**那台电脑**上的服务，需要在那台机器上跑服务并登录 |

所以这个面板的形态是：**一份代码 + 每人各自的本地服务**。公网地址只是「能直接打开界面」的入口。

### 一个需要知道的安全细节

「允许访问本地网络」这个授权是**按站点**给的。你一旦对某个页面点了「允许」，
那个页面就获得了访问你本机服务的能力。所以：

- 只对你信任的页面点「允许」
- 不用的时候把伴随服务关掉（`Ctrl+C`），这样即使授权还在也无处可查
- 想撤销授权：地址栏左侧的站点设置里可以改

### 可选：启用访问令牌与来源白名单

默认零配置：任何来源的页面都能调用服务。想收紧时用环境变量开启，**不需要改代码**，
不设置就与旧版完全一致（启动日志会打印 `[!]` 提醒）。

Windows cmd（只对当前窗口生效）：

```bat
set CBG_PANEL_TOKEN=换成你的随机口令
set CBG_ALLOWED_ORIGINS=https://smaxhero.github.io,http://127.0.0.1:5173
node tools\cbg\scraper-service\server.mjs
```

PowerShell：

```powershell
$env:CBG_PANEL_TOKEN = "换成你的随机口令"
$env:CBG_ALLOWED_ORIGINS = "https://smaxhero.github.io,http://127.0.0.1:5173"
node tools\cbg\scraper-service\server.mjs
```

也可以用 CLI：`--token <口令>`、`--allowed-origins <逗号分隔列表>`。
想长期生效（双击 `start.bat` 也能读到）用 `setx`，然后重开终端：

```bat
setx CBG_PANEL_TOKEN "换成你的随机口令"
setx CBG_ALLOWED_ORIGINS "https://smaxhero.github.io,http://127.0.0.1:5173"
```

开启后可以这样验证（`/api/health` 永远免令牌，用来探活）：

```bash
curl http://127.0.0.1:8791/api/health
# 不带令牌：401 {"ok":false,"error":"UNAUTHORIZED",...}
curl http://127.0.0.1:8791/api/result
# 带令牌：200
curl -H "X-Panel-Token: 你的口令" http://127.0.0.1:8791/api/result
```

两点注意：

- **内置网页面板没有令牌输入框**：开启令牌后，面板的请求会收到 401。纯浏览器使用建议只配置
  `CBG_ALLOWED_ORIGINS`；令牌更适合脚本 / 自建代理 / 后续接入的客户端。
- 白名单里写 `null` 可以放行 `file://` 页面；不配置白名单时仍沿用 `*` 的宽松行为。

细节与 SSRF、请求体上限等改动见 [security.md](security.md)。

## 四、想改代码 / 提 PR

1. Fork → 建一个描述性的分支（如 `feat/xxx`）
2. 本地按第一节跑起来，改完至少验证：

   ```bash
   cd cbg-web
   npm run typecheck     # 类型检查
   npm run build         # 生产构建
   npm run dev           # 手动点一遍受影响的功能
   ```

3. 推到你自己的 fork，然后在原仓库发起 Pull Request
4. PR 的工作流会在**你的仓库**里跑，不会影响原仓库的 Pages

改动前的建议：先读 `cbg-web/README.md` 的「开发时踩过的坑」一节，
里面记了几个**不会报错、只会安静给出错误结果**的陷阱（参数倍率、两个长得一样的 ID、
Effect 依赖导致的无限更新循环等），能省下不少排查时间。

## 五、许可与使用边界

- 抓取的是藏宝阁**公开列表页的聚合信息**；
- 请求由**使用者自己已登录的浏览器**发出，本工具不读取、不保存账号密码；
- 请控制查询频率（默认已内置节流：4 秒/页、单次最多 8 页）；
- **仅供个人比价参考，不要用于商业用途或二次分发数据**；
- 请遵守藏宝阁用户协议，因使用不当导致的账号风险由使用者自行承担。

> 仓库目前未附许可证文件。在补充许可证之前，默认「保留所有权利」。
