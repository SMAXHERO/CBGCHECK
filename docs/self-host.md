# 别人怎么用这个仓库

三种用法，按实际需要选。**绝大多数人只需要第一种。**

---

## 一、clone 到本机自己用（主要用法）

这个工具本质是**本机工具**：界面在你浏览器里，但拿数据要靠本机一个伴随服务
（它借用一个已登录藏宝阁的浏览器去发请求）。所以真正要用，就在本机跑。

```bash
git clone https://github.com/SMAXHERO/CBGCHECK.git
cd CBGCHECK

# 终端 1：启动伴随服务（会弹出一个独立的浏览器窗口）
node tools/cbg/scraper-service/server.mjs
#   └─ 在那个窗口里登录一次藏宝阁（只需一次，登录态存在本地 profile 里）

# 终端 2：启动面板
cd cbg-web
npm install
npm run dev
#   └─ 浏览器打开 http://127.0.0.1:5173
```

### 需要预装什么

| 依赖 | 是否必需 | 说明 |
|---|---|---|
| **Node.js ≥ 20** | ✅ 必需 | 面板（Vite）和伴随服务都是 Node 程序 |
| **Edge 或 Chrome** | ✅ 必需 | 伴随服务要拉起一个浏览器窗口发请求；Windows 自带 Edge |
| **Python ≥ 3.9** | ⬜ 可选 | 只有 `tools/cbg/` 下的核对脚本用得到，跑面板不需要 |

### 常见疑问

**换网络要重新配置吗？**
不用。服务和界面都在本机 `127.0.0.1` 上通信，换 Wi-Fi 不影响。
唯一变化是请求的出口 IP 变了——家用宽带/手机热点一般没问题；
如果是公司或机房网络，风控可能更容易被触发（表现是提示需要滑块验证）。

**换电脑呢？**
上面那套依赖重新装一遍，并且**在新电脑上重新登录一次藏宝阁**。
登录态存在 `tools/cbg/scraper-service/profile/`，该目录被 git 忽略（它含 Cookie，
绝不能提交），所以不会跟着代码走——这也正是它安全的原因。

**登录态会过期吗？**
会。失效时界面会显示「需要登录藏宝阁」，回到那个浏览器窗口重新登录即可。

## 二、Fork 一份，部署到自己的 GitHub Pages

> ⚠️ **先说清楚**：部署出来的地址打开是**空的引导页**，不是能查数据的面板。
> 因为公网页面访问不了你电脑上的 `127.0.0.1`（Chrome 的本地网络访问保护，详见根 README 开头）。
> 这一步的意义是「有一份属于自己的代码副本 + 自动构建验证」，不是获得一个可用服务。

步骤：

1. 仓库页右上角 **Fork** → **Create fork**，得到 `你的用户名/CBGCHECK`
2. 在**你自己的 fork** 里打开 **Settings → Pages**
3. **Source 选择 `GitHub Actions`**（不要选 "Deploy from a branch"）
4. 到 **Actions** 标签，若提示工作流被禁用，点
   **I understand my workflows, go ahead and enable them**
5. 之后每次 push 到 `main` 分支，工作流会自动构建并部署，约 1 分半
6. 访问 `https://你的用户名.github.io/CBGCHECK/`

### 不需要改任何代码

`cbg-web/vite.config.mjs` 用的是 `base: './'`（相对路径），
所以仓库叫 `CBGCHECK`、`cbg-panel` 还是别的名字都能直接跑，不用改配置。

### 三个容易卡住的点

| 现象 | 原因与处理 |
|---|---|
| Pages 里找不到 GitHub Actions 选项 | 仓库必须是 **Public**——私有仓库的 Pages 需要付费计划 |
| 部署成功但页面是 404 | Source 选错了，要选 `GitHub Actions`，不是分支部署 |
| Actions 里没有任何工作流 | fork 来的仓库默认可能禁用工作流，去 Actions 页手动启用一次 |

## 三、给自己的/别人的面板接入服务

**做不到跨机器共享**：公网页面访问不了别人机器上的 `127.0.0.1`。
每个人必须各自跑一份伴随服务、登录各自的藏宝阁账号。

如果你想在**同一个仓库**里换掉默认条件、改界面，直接改 `cbg-web/src/config/defaults.ts`
等文件，然后提交、推送，工作流会重新部署。

## 四、想改代码 / 提 PR

1. Fork → 建一个描述性的分支（如 `feat/xxx`）
2. 本地按第一节跑起来，改完至少验证：

   ```bash
   cd cbg-web
   npm run typecheck     # 类型检查
   npm run build         # 生产构建
   npm run dev           # 手动点一遍受影响的功能
   ```

3. 推到你自己的 fork，然后在原仓库发起 Pull Request
4. PR 的工作流会在**你的仓库**里跑，不会影响原仓库的 Pages

改动前的建议：先读 `cbg-web/README.md` 的「开发时踩过的坑」一节，
里面记了几个**不会报错、只会安静给出错误结果**的陷阱（参数倍率、两个长得一样的 ID、
Effect 依赖导致的无限更新循环等），能省下不少排查时间。

## 五、许可与使用边界

- 抓取的是藏宝阁**公开列表页的聚合信息**；
- 请求由**使用者自己已登录的浏览器**发出，本工具不读取、不保存账号密码；
- 请控制查询频率（默认已内置节流：4 秒/页、单次最多 8 页）；
- **仅供个人比价参考，不要用于商业用途或二次分发数据**；
- 请遵守藏宝阁用户协议，因使用不当导致的账号风险由使用者自行承担。

> 仓库目前未附许可证文件。在补充许可证之前，默认「保留所有权利」。
